## 📨 学生转发消息路由(ta-assistant)

**任何以 `【转发学生提问】` / `【转发同学提问】` / `【转发学生消息】` / `[转发学生提问]` 开头的消息,都必须交给 `ta-assistant` 技能处理,不要自己回答。**

原因:这类消息是助教从微信转发来的学生提问或作业补交,必须走后端服务:

- **补交登记**要写进 Excel 补交表(自己回答 = 学生没被登记上)
- **课程答疑**要以课程资料库为准(自己回答 = 可能给出过时/错误的资料链接)

做法:按 `skills/ta-assistant/SKILL.md` 调用 bridge,把整条消息原文喂进去,然后把返回 JSON 的 `reply` **原样**发回微信。

## 📝 助教的 `【记录】` 指令也要走同一条路

**任何以 `【记录】` 开头的消息,同样必须交给 `ta-assistant` 技能,不要自己回答。**

那是助教在把"刚答完的问题 + 标准答案"记进 FAQ 库(`Q:/A:` 格式,下次学生问到时自动用上)。
整条原文喂进去,`reply` 原样发回 —— **`✅` 才是记上了,`❌` 就是没记上**,别替它说"记好了"。

两条禁令:

- **不要替助教改写问题或答案** —— 后端记的就是你交上去的原文;
- **不要"顺手"删掉里面的学号/姓名再提交** —— 后端拒收就是想让助教知道,
  你悄悄清理等于把提示吞了,而 FAQ 里的内容是要发给学生的。

五种返回值怎么回:

| `type` | 你发什么 |
|---|---|
| `submission` | 原样发 `reply`(登记结果,一个字都别改) |
| `question` | 原样发 `reply`;若有 `sources`,末尾另起一行 `参考:文件1, 文件2` |
| `record` | 原样发 `reply`(给助教本人的回执) |
| `skip` | 什么都不发(静默) |
| `error` | "助教机器人暂时不可用,请稍后再试" |

后端挂了就如实说挂了,**不要猜答案、不要编登记结果**。
