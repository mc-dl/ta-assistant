# ta-assistant —— 课程助教后端

助教(老师)在微信里把学生的提问**转发**给你时,消息会带一个转发前缀。
这类消息**不是聊天**,而是要求你调用本技能,把请求转给本机运行的后端服务 `ta-assistant`。

后端会做两件事之一:

1. **补交登记** —— 抽取学号/姓名/第几次作业,写进 Excel 补交表,返回登记结果
2. **课程答疑** —— 先把提问分档(具体题号 / 课程事务 / 学科概念),再查 FAQ 和
   课程资料库(BM25 检索),最后让大模型作答:
   - 具体题号(如「1.36 怎么做」)→ 只认资料里那道题的解答,查不到就明说没找到
   - 课程事务(交作业、截止、成绩、考试安排)→ 只认资料,资料没有就说"不确定"
   - 学科概念(什么是叠加原理)→ 允许大模型用自己的通用教材知识讲解,
     并挂上资料库里相关的作业题当例子

服务范围是**两门课**:数字电路与逻辑设计实验(一)、电路基础(理论课)。
资料库里两门课的资料都在,不用在调用前判断是哪门课 —— 直接交给后端即可。
**分档和作答口径全部由后端决定,你不需要(也不应该)替它判断。**

## 一、什么时候触发

有**两类**消息要走本技能。

### 1. 学生转发(助教转来的学生消息)

消息**去掉前导空格后**以以下任一前缀开头,就必须用本技能:

| 前缀 | 说明 |
|---|---|
| `【转发学生提问】` | 标准(全角方头括号 U+3010/U+3011) |
| `【转发同学提问】` | "同学"变体 |
| `【转发学生消息】` | "消息"变体 |
| `[转发学生提问]` | 半角方括号变体 |

**只要带前缀就必须走技能,不要自己回答**,哪怕你觉得问题很简单 —— 因为补交登记必须落到 Excel 里,答疑必须以课程资料为准。

### 2. 助教的记录指令 `【记录】`

消息去掉前导空格后以 `【记录】` 开头时,这是**助教自己发的**命令:
把刚答完的那句话(问题 + 标准答案)写进 FAQ 库,以后学生问到时自动就用上了。

典型长这样:

```
【记录】问题:仿真软件 Proteus 在哪下载?
标准答案:课程群文件里有个压缩包,解压后按说明装。
```

它**不是**学生消息、更不是聊天。同样**必须**交给后端 —— 记录要落盘、还要做
查重和个人信息检查,这些只有后端会做。

两条规矩,和上面的学生转发一样重要:

- **整条原样转**,不要替助教改问题或答案 —— 后端记录的就是你给的原文;
- **不要"顺手"把里面的学号、姓名删掉再转**。后端拒收(含学号/姓名的条目)
  是为了**让助教知道**并自己决定怎么写;你悄悄清理掉再提交,提示就被你吞了,
  而写进 FAQ 的东西是要发给学生的。

消息**不带**上述任何前缀时,不是转发也不是记录,正常按聊天处理即可(通常不需要回复,静默)。

## 二、怎么调用

用 `bash` 工具执行下面这条命令,**把整条消息原文(含前缀)原样交给 `--message`**:

```bash
/home/jj/ta-assistant/.venv/bin/python \
  /home/jj/ta-assistant/scripts/openclaw_bridge.py \
  --message '【转发学生提问】这里替换成整条消息原文'
```

关键要点:

- **整条原文**,含前缀。后端靠前缀判定这是哪一类消息,**前缀绝不能删**
  (学生转发的靠它认"学生消息",`【记录】` 靠它认"助教的记录指令")。
- **单引号包裹**参数(消息里有单引号时用 POSIX 写法 `'\''` 转义)。
- 命令可以从任意目录执行,脚本自己会处理路径。
- **加超时**:答疑要调大模型,正常 3-15 秒,给 120 秒超时即可。
- 脚本 **stdout 只输出一行 JSON**;不要往里追加任何东西,也不要去看 stderr(那是日志)。

## 三、返回的 JSON 契约

```json
{"type": "submission", "reply": "✅ 已登记:..."}
{"type": "question",   "reply": "...", "sources": ["xxx.pdf", "yyy.pdf"]}
{"type": "record",     "reply": "✅ 已记录,FAQ 现在能被检索到 38 条。..."}
{"type": "skip",       "reply": "(非学生消息,未处理)"}
{"type": "error",      "reply": "系统错误:...", "trace": "..."}
```

`type` 的五种取值:

| type | 含义 | 你该做什么 |
|---|---|---|
| `submission` | 补交已登记(或登记失败原因) | **原样**发 `reply` |
| `question` | 答疑结果 | **原样**发 `reply`;有 `sources` 则在末尾另起一行加 `参考:文件1, 文件2` |
| `record` | 助教的 `【记录】` 回执:记上了 / 没记上(附原因) | **原样**发 `reply`(这条是回给助教本人的) |
| `skip` | 不是学生转发 / 正文为空 | **不发任何内容**(静默) |
| `error` | 后端炸了 | 发"助教机器人暂时不可用,请稍后再试",并把错误写进 `memory/YYYY-MM-DD.md` |

`record` 的回执**以 `✅` 开头 = 真记上了,以 `❌` 开头 = 没记**,后面写着为什么。
**`❌` 的时候绝不能回一句"好的,已经记下了"** —— 助教就此以为库里有了这条,
下次学生问同样的问题还是答不上来,而且没人会再查一遍。**说没记上就是了。**

## 四、回复规则(重要)

- 把 `reply` 字段的内容**原样发出**。
- **不要改写、润色、总结、翻译**;不要加表情、不要加"我觉得"、不要加额外解释。
- 尤其 `type=submission`:里面是登记结果(学号/姓名/第几次),"差不多"地转述会误导学生。
- `reply` 如果很长(资料原文),也要完整发出,不要截断。
- `type=record` 的回执是**给助教看的**,`❌` 就是没记上,别替它说"记好了"。
- 退出码不是 0 时(`type=error`),**绝不**回复"已登记",只能回复不可用。

## 五、失败与兜底

| 情况 | 处理 |
|---|---|
| 命令超时 / 没有输出 | 回复"助教机器人暂时不可用,请稍后再试" |
| stdout 不是合法 JSON | 同上,并把原始输出记进 `memory/YYYY-MM-DD.md` |
| `type=error` 且 `reply` 里含 `LLM`/`大模型` | 说明大模型额度或网络有问题,照样把 `reply` 发出(后端已降级为资料原文),并提醒助教检查额度 |

## 六、不要做的事

- 不要直接修改 `~/ta-assistant` 里的代码、`.env`、Excel 补交表 —— 要改就先问助教(老师)。
- 不要把 `.env`、API Key、微信凭据打印到聊天里。
- **不要自己回答学生的问题**,哪怕你觉得很简单。答疑一律交给后端:
  - 后端的稿子可能包含"通用教材知识,供参考"的讲解(概念题允许);
  - 但**事务信息**(交作业方式、截止时间、评分、考试安排)后端是死守资料的,
    你若自己补充一句"好像是下周五交",就把这条防线废掉了。
- `reply` 里如果出现"这个我不确定,建议问任课老师",那是**后端的判断结果**,
  **照原样发出**,不要替换成你自己知道的答案。
- **不要替助教决定"这条 FAQ 该不该记"**。`❌` 的那些理由(含学号、重复、格式不对)
  都是后端有意拦的,你绕过哪一条,哪一条就白做了。
- **不要自己改写助教的问题或答案再提交**。后端记的就是你交上去的原文,
  改写等于替助教改了语料的措辞。

## 七、手工自检(排查时用)

```bash
# 后端本体是否正常:应当输出一行 JSON,type=submission
# 注意:下面用的是**假名字/假学号**,自检时不要拿真实学生的姓名学号来试
/home/jj/ta-assistant/.venv/bin/python \
  /home/jj/ta-assistant/scripts/openclaw_bridge.py \
  --message '【转发学生提问】测试同学 20259999999 漏交第1次作业'

# 【记录】这条通路是否正常:应当输出 type=record,而且是 ❌(因为有学号)
# 故意这么造:它**会被拒收**,所以既能验证通路、又不会真往 FAQ 里写东西。
/home/jj/ta-assistant/.venv/bin/python \
  /home/jj/ta-assistant/scripts/openclaw_bridge.py \
  --message '【记录】问题:测试 20259999999 在哪交作业
标准答案:交给学委'

# 看后端日志(每次调用都会写)
tail -f /home/jj/ta-assistant/data/logs/$(date +%Y-%m).log
```

**自检 `【记录】` 时千万不要拿一条"正常"的问答去试** —— 那会真的写进助教的
`常问问题.txt`,而那份文件是手写的、没有版本库兜底。用上面这条会被拒收的。
